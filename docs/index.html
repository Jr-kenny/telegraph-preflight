OneShot

A preflight check for listing a token — where the verdict itself is proven. Every run is written into a single record, hashed, and anchored on-chain, so anyone can check that the answer you see is the answer the checks actually produced. Sepolia testnet

Three kinds of trust

Telegraph proves the checks were bought. OneShot proves the verdict is honest. That takes three things, and every run below shows all three.

1. Data cross-checked

The numbers are checked against independent sources — DexScreener for liquidity, honeypot.is for sellability — so one wrong answer from one miner does not pass unnoticed.

2. Answer verified

Every paid check comes back with a receipt (a signal hash). Anyone can fetch that receipt from the Telegraph node and see the exact result the miner returned.

3. Execution proven

The whole run — legs, results, verdict, cost — is written into one record, hashed with SHA-256, and the hash is anchored on Sepolia. Runs are numbered in order, so none can be silently re-rolled or rewritten. node verify.js re-checks all of it.

Two real runs

Both runs are on Sepolia testnet, paid in testnet USDC ($0.04 each, 4 paid checks). Both verdicts are REJECT. Nothing here was listed. That is the honest result the evidence produced — and the point is that the record proves it, whichever way the verdict falls.

Why both runs reject. A preflight that only ever says “list” proves nothing. USDC was rejected because the wash-trading miner flagged its pool at 81% wash volume; HNP was rejected because it cannot be proven sellable. OneShot records the verdict the evidence actually produced — and the anchor plus verify.js let anyone confirm that record, instead of taking the tool’s word for it.

How it works

OneShot runs four paid Telegraph checks (wash trading, security review, liquidity depth, sanctions screening) for $0.04 testnet USDC, then adds two free checks — a honeypot sell simulation (honeypot.is) and a DexScreener liquidity cross-check — before deciding. After the checks, it builds one canonical execution record, hashes it, and anchors the hash on Sepolia with a 0-value transaction carrying the hash as calldata. No run is anchored if it produced zero receipts.

To check a run yourself:

git clone https://github.com/Jr-kenny/telegraph-preflight
cd telegraph-preflight
node verify.js results/preflight-0x52a7ed336eec9580bb9cc87e5bb8d5a35b844029.json

The verifier recomputes the record hash, confirms the anchor transaction on Sepolia carries that hash, re-fetches each signal from the Telegraph node and checks the results match the record, re-derives the verdict from the re-fetched evidence, and re-checks the honeypot result against honeypot.is. It exits 0 only if every check passes.
